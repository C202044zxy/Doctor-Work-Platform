# 本地热更新启动与 M3 手动测试

适用：`codex/b-w2-w3` 整合新版 main 后的代码。任务以 [01-任务安排](01-任务安排.md) 为准；本指南不修改模块归属。M3 负责人：李奕儒。

## 1. 为什么保存代码就会更新

```text
浏览器 http://127.0.0.1:5173
  ├─ Vue / CSS ← 本机 Vite 监听 frontend/src，推送 HMR
  └─ /api、/uploads、/ws ← Vite 代理到本机 FastAPI :8000
                                ├─ uvicorn --reload 监听 backend/app
                                ├─ backend/doctor.db（本地 SQLite）
                                └─ 127.0.0.1:16379 → Docker Redis :6379
```

前后端直接读取你正在编辑的源码，不从 Docker 镜像读取代码。前端通常局部更新，后端自动重启工作进程。后端重启会断开 WebSocket，聊天重连后按消息 ID 补齐；进行中的视频会结束，需要重新拨打。数据库和图片文件不因重载清空。

## 2. 第一次启动（Windows）

先安装 Git、uv、Node.js 22.12+、Docker Desktop，启动 Docker Desktop 的 Linux 容器引擎。

```powershell
winget install --id astral-sh.uv -e
winget install --id OpenJS.NodeJS.LTS -e
```

安装后重新开 PowerShell。进入**包含 backend、frontend、scripts 的仓库根目录**，不是外层存放补丁的目录。更新已有本地分支时，先确认 `git status` 没有未保存改动：

```powershell
git switch codex/b-w2-w3
git pull --ff-only origin codex/b-w2-w3
```

若旧的完整 Docker 栈占用了 5173 或 8000，在对应旧仓库目录执行 `docker compose stop frontend backend`。使用 `compose.sqlite.yaml` 启动的栈要带原来的 `--env-file .env.server -f compose.sqlite.yaml` 参数。不要删除数据卷。

运行：

```powershell
.\scripts\dev.ps1
```

执行策略阻止脚本时：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1
```

脚本会依次：安装锁定依赖；仅在缺失时创建 `backend/.env` 并生成本机随机密钥；启动独立的 `doctor-work-dev` Redis；执行 Alembic 迁移、基础与演示种子；启动 Uvicorn reload 和 Vite。已有 `.env` 不覆盖；如果已有 `doctor.db` 却丢了 `.env`，应找回原密钥，不能重新生成密钥去读旧加密数据。

开发入口固定把当前进程的 Redis 地址设为 `redis://127.0.0.1:16379/0`；数据库、SMTP 等仍读取 `backend/.env`。已有 `.env` 如指向共享数据库，请先改成自己的开发库再运行。数据来自本地 SQLite，不会自动复制 Docker 数据卷中的账号和患者。

- 页面：http://127.0.0.1:5173
- API 文档：http://127.0.0.1:8000/docs
- 健康检查：http://127.0.0.1:5173/api/health/ready

## 3. 日常开发与停止

依赖已经安装、锁文件没变时：

```powershell
.\scripts\dev.ps1 -SkipInstall
```

只准备环境，不启动前后端：

```powershell
.\scripts\dev.ps1 -NoServe
```

在启动终端按 Ctrl+C 停止前后端；Windows 会终止 Uvicorn reload 的整个子进程树。Redis 保留运行；需要停止时：

```powershell
docker compose -f compose.dev.yaml stop
```

日志位于 `backend/runtime/api.log`、`api-error.log`、`web.log`、`web-error.log`，可另开终端查看：

```powershell
Get-Content .\backend\runtime\api-error.log -Wait
```

| 改动 | 操作 |
|---|---|
| Vue、CSS、普通前端代码 | 保存后看页面 |
| `backend/app` 下 Python | 保存后等自动重载 |
| `.env`、启动参数 | 停止再启动 |
| `uv.lock`、`package-lock.json` | 不带 `-SkipInstall` 重启 |
| 数据模型 | 新增迁移，同时更新 `scripts/build_db.py` 表契约，再执行迁移 |
| Dockerfile、发布镜像 | 发布时才构建；本地普通源码修改不需要 |

Linux / macOS 使用 Bash 4.3+：`bash scripts/dev.sh`；日常 `bash scripts/dev.sh local --skip-install`。它与 Windows 使用同一 Redis Compose 和本机热更新方式。`backend/start.*` 仍保留不依赖 Docker 的本机 Redis 回退入口，CI 的 Windows 环境使用 `backend/start.ps1 -Reload`。

1. `dr_wang` 打开 Consultations，输入 `P20260001`，点 New consultation；`dr_li` 搜索同一患者，在 Waiting 中点 Accept。双方打开同一房间，确认 Active / Connected。

5. 点 End consultation，确认 Ended、`ended_at`，发送和发起视频禁用；历史仍可读。服务端也会拒绝继续写入，不只靠按钮控制。

8. 上传伪装图片、超 5 MiB 文件应失败；正常图片即使用 `../evil.png` 文件名，也会被随机改名并限制在 uploads 目录内，不会保留原路径。

未接听呼叫 25 秒超时；已断开的信令连接通过 5 秒探测、20 秒无响应关闭，清理通话和 Redis 在线租约。操作系统崩溃或强杀进程不能保证最后一条通话日志落库，但数据库中不会有无结束时间的“进行中”通话记录。

## 6. 视频测试的环境边界

- 本机访问 `http://127.0.0.1:5173` / localhost 可请求媒体权限；其他设备访问普通 `http://局域网IP` 通常不允许摄像头，需要可信 HTTPS。仅改成 `--host 0.0.0.0` 不能解决这个限制。

媒体权限依据：[MDN getUserMedia 安全上下文说明](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia#privacy_and_security)。
- 当前 `iceServers: []`，基线是同机或网络可直接互通的局域网；没有配置 STUN/TURN，不承诺跨公网成功。跨公网需团队配置 TURN 并验证防火墙、HTTPS/WSS。
- 无录像文件，没有实现 S3 模拟回放。Call history 只是通话元数据。
- M5 会诊模型/参与者服务未合入；当前 `/ws/chat/{room_id}` 的数字 ID **只代表问诊 ID**。不能把会诊 ID 当问诊 ID 使用；复用路由的跨模块接入仍待 M5 负责人联调。
- 服务器使用一个 Uvicorn worker，房间广播和信令在该进程内。不要直接扩成多 worker；需要先实现 Redis Pub/Sub 与分布式通话状态。

## 7. 常见问题

- 页面 401：模拟登录不是真实会话，或 Token 已过期；使用实际邮箱登录或上述本地 CLI 测试会话。
- Redis 503 / 无法登录：`docker compose -f compose.dev.yaml ps` 检查健康状态；确认 Docker Desktop 已启动，16379 未被其他服务占用。
- 看不到旧患者：Docker 卷与本地 `backend/doctor.db` 是不同数据库。不要通过重新生成加密密钥“修复”数据问题。
- 页面没有变化：确认访问 5173 的 Vite 页面，而不是旧 Nginx 的 8080 页面；查看 web 日志确认没有端口占用。
- 多个 Alembic heads：先确认已经拉取本分支最新提交；本次 merge revision 合并了旧问诊与 main 审计两条迁移链。不编辑旧迁移的 revision/down_revision 来绕过报错。
- 同一人接了自己创建的问诊：图文仍可用，但没有另一个视频参与者。测试时由 dr_wang 创建、dr_li 接诊。

普通启动只升级，不清库。需要重建独立验收库时，在仓库根执行 `uv run --project backend python scripts/build_db.py --db backend/runtime/manual-test.db`；不要把重建默认库当成每次启动步骤。

## 8. Redis disabled / 登录 503 的定位与修复（2026-09-19）

本次现场检查：D 盘旧仓库仍为 `56b5f9e`；运行中的 API `/api/health/ready` 返回 `redis: disabled`，但 HTTP 为 200。不是“Redis 容器启动后被登录弄坏”，而是旧 API 未读取 Redis 配置。旧健康检查把未配置也视为 ready，造成误导。即使启动了新的 Redis，已经运行的旧 API 也不会自动更新环境变量。

1. 在原来的 API / Vite 启动终端按 Ctrl+C。先确认没有未提交改动，再更新**实际启动的仓库**：

   ```powershell
   cd D:\AAA-Finally\Doctor_Work_Platform\Doctor-Work-Platform
   git status --short --branch
   git switch codex/b-w2-w3
   git pull --ff-only origin codex/b-w2-w3
   powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1
   ```

   如果当前在本次修改使用的 C 盘工作副本，则进入 `C:\Users\19239\Documents\ChatGPT\Doctor_work_platform\Doctor-Work-Platform` 启动。两个副本不要同时运行；启动的副本才是热更新监听的源码目录。

2. 新脚本在启动前检查 8000/5173，端口被占用就退出，不会连到旧 API 或自动把前端挪到 5174。仅在 DB 和 Redis 都为 `ok` 后显示启动成功；Redis 未配置时 readiness 改为 503。
3. 查看依赖：

   ```powershell
   docker compose -f compose.dev.yaml ps
   docker compose -f compose.dev.yaml exec redis redis-cli ping
   Invoke-RestMethod http://127.0.0.1:8000/api/health/ready | ConvertTo-Json -Depth 4
   ```

   预期 `PONG`、`data.db=ok`、`data.redis=ok`。开发 Redis 映射 **16379**；Docker 容器间地址 `redis:6379` 不能给本机 API 使用。脚本会检查 Docker 引擎、等待 Redis，并设置 `restart: unless-stopped`；手动 stop 后仍需运行开发脚本重新启动。
4. `-NoServe` 仅准备环境，它设置的进程环境不会传播给别的终端。若坚持手动运行后端，必须在**同一终端**设置：

   ```powershell
   cd backend
   $env:REDIS_URL = 'redis://127.0.0.1:16379/0'
   $env:APP_ENV = 'dev'
   uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
   ```

   仍需保留原 `backend/.env` 中 JWT / 患者加密密钥。已有库缺失密钥时不要为了启动而重新生成。推荐统一运行 `scripts/dev.ps1`，它会传递正确配置。

## 9. 模拟短信接口与手测

模拟发送不调用运营商。`APP_ENV` 默认 production；只有开发模式允许短信发送、查看和验证（否则 404）。发送响应不含验证码；仅 ticket 查看接口与管理员 outbox 在 dev 下可返回明文，属于 S1 文档登记的契约例外，不写入审计日志。

| 接口 | 请求 / 权限 | 行为 |
|---|---|---|
| `POST /api/auth/login` | username、password | 取得 300 秒 ticket |
| `POST /api/auth/sms/send` | ticket、phone | 模拟发送，返回 mock、masked_phone、cooldown=60、expires_in=300 |
| `POST /api/auth/sms/preview` | ticket（JSON 请求体） | 仅查看当前 ticket 的验证码；不把 ticket 放 URL；响应 no-store |
| `POST /api/auth/sms/verify` | ticket、code | 一次性校验，返回真实 JWT 与 mock=true |
| `GET /api/notify-outbox?page=1&size=20` | admin Bearer Token | 倒序分页模拟发送记录，非 admin 403；过期或非 dev 的 code 为 null |

在 `/docs` 中按表顺序执行，或在登录页使用 **View simulated SMS**。查看接口只是读取，不会重新发送或重置验证码有效期。发送频率与邮箱共用：60 秒冷却、每日上限；429 的 `Retry-After` 为剩余冷却秒数。两渠道共用 5 次错误验证码计数，成功消费后同一 ticket 不可再次使用。重新登录获取 ticket 不能绕过账号级发送限流。

手测：正常登录；重复发送应 429；重复提交同一码应 401；等待 5 分钟应过期；使用另一 ticket 查看应 404；关闭 Redis 后登录应 503、ready 应 503。重启 Redis 后重新登录，不复用失效 ticket。生产默认关闭模拟入口；这不构成真实短信二次认证。

S1 当前只交付短信登录、受限查看和管理员记录查询；微信、M6 提醒写 outbox、全局模拟手机最近 5 条浮层尚未实现，不将 S1 全部标为完成。注册仍走原有邮箱验证，本次未改为短信注册。


可选浏览器复验：安装 Playwright 与 Edge 后，开发服务运行时执行 `node scripts/verify_sms_browser.cjs`（已有 Playwright 可设置 `PLAYWRIGHT_MODULE_PATH`）；默认使用 dr_wang / Demo@2026，密码可由 DEMO_PASSWORD 覆盖。验证会真实模拟发送一次，连续重跑须遵守 60 秒冷却。
