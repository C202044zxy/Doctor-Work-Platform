## 数据流与边界

1. HTTP 请求经过默认鉴权，数据访问统一落到 `patient_scope/visible_patient`。跨科室记录查询结果为空，单对象访问越范围返回 404；已有数据范围但缺会话参与身份的写入/信令返回 403。
2. 创建问诊的工作人员充当患者协助端；接诊医生是另一个参与者。没有患者客户端。部门内其他有范围的医生和管理员可以只读查阅问诊记录，不能因此发送消息或加入视频。
3. 图片经内容解码校验、5 MiB 入站上限、25MP 像素上限、重新编码、随机文件名后落盘。未绑定图片仅上传者可读；绑定会话后按患者数据范围只读访问。浏览器携带 Bearer 取 blob，不提供匿名文件下载。
4. 消息写入 `consult_message`，更新列表预览，提交事务后广播持久化 ID。`(consultation_id, sender_id, client_id)` 唯一键支持丢确认后的重试；相同 key 不同内容返回 409。
5. 前端按服务端 ID 去重合并；`before_id` 逆序加载旧消息，`after_id` 正序补齐离线消息。使用 ID 游标可避免同一时间戳导致漏消息；这实现了重连补齐需求。
6. 记录中心与 CSV 共用 `RecordFilters.statement`，不额外扩大数据范围。关键词按字面包含匹配，用 EXISTS 避免同房间多条匹配导致重复会话。日期按 Asia/Shanghai 的创建日期区间，结束日期含整天。CSV 含 BOM、attachment 文件名，并中和以公式前缀开头的文本。
7. 视频媒体走浏览器之间的 WebRTC，不经过 FastAPI。WS 只传 SDP/ICE 等信令。呼叫绑定具体两个 WS 连接，不能被同账号其他标签或普通房间旁观者劫持；每条入站事件和出站事件仍检查 JWT/数据范围。
8. 呼叫 25 秒未接通结束；失联连接在 20 秒无入站响应后关闭（每 5 秒探测），触发结束。call_log 只存结束记录，接通到挂断时长由服务器计算；未接通时长为 0。服务正常关闭会写 server_restart；强杀/崩溃最后一条可能丢失，不能宣称可靠持久通话事件日志。
9. 当前 ChatHub、呼叫状态都在单个 API worker 内。Redis 用于认证和在线租约，不承担跨进程消息总线。生产使用多个 worker 前必须另做 Pub/Sub 和分布式状态。

## 契约变更

- `Consultation.is_participant` 只控制前端可写体验，后台独立检查。
- `/records`、`/export` 在原 `patient_no/q/from/to` 外增加可选 `patient`（姓名包含或患者号精确）。CSV 导出全部命中记录，分页列表用 total 表示同一全集。
- 新增受保护 `/uploads/{filename}` 下载契约，补实际上传错误码 413 / 422。
- `/calls` 实现已有 GET/POST 契约；可选 `call_id` 作为重试键，GET 返回 `end_reason`。POST 校验时序/时区/时长，不允许伪造未来时长；正常浏览器不调用 POST，由服务器信令结束后自动落库。
- WS 增加 `call_connected/call_end/call_reject`，以及既有 ping/pong/status/error 事件说明。握手拒绝在实际 ASGI WebSocket 升级前执行。
