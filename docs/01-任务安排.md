## 1. 项目范围与本次重构结论

### 1.1 项目定位

医生工作平台（Doctor Work Platform）：以**患者档案**为数据核心的院内工作平台，覆盖 2FA 登录与三级权限、患者信息与过敏警示、电子病历（含医嘱过敏拦截）、在线问诊（图文 + 视频）、远程会诊、患者健康管理；审计日志为横切能力。

### 1.2 为什么废弃旧编号

重构前仓库内有 13 份文档互相矛盾，其中 4 份自称"唯一权威来源"，同一批工作存在 3 套并行编号（`T01–T37`、`M01–M07`，以及散落在契约与审计记录里的旧 ID）。实际后果是状态标注与代码事实严重脱节：

1. **把零代码的模块标成"已完成"**。典型失真条目：T25（WebSocket）、T26（图文消息）、T30（会诊）、T33（体征）、T13（患者）、以及 S1（短信验证码）。这些在旧文档里被标为完成，代码库中不存在对应实现。
2. **排期文档用单字母代号指代成员**，与真实负责人对不上，公开文档里无法追责。**该代号体系自本版起作废，任何文档不得再使用。**
3. **技术选型与实现不符**：排期文档写 MySQL 8.4，当前实现与决策是 **SQLite + Redis**。
4. **范围反复**：短信、人脸、录像、IoT、监控、动态 RBAC 在旧文档中被砍掉又被收回，口径互相否定。

### 1.3 本次重构结论（四条）

1. **新编号 M0–M9（主模块）/ S1–S6（模拟模块）/ D01–D07（文档与交付）是唯一编号体系。** 旧编号 `T01–T37` 与 `M01–M07` **只允许出现在 §7 新旧编号对照表**，不得出现在任务清单、分支名、PR 描述、文档正文与演示脚本中。
2. **状态只承认代码事实。** 状态列取值只有 4 个：`未开始` / `进行中` / `部分完成` / `已完成`。**没有代码就是 `未开始`**；有代码但测试场景未逐条跑过，最多 `部分完成`。模拟实现即使代码完整，也必须标注"（模拟）"。
3. **模拟必须可识别。** S1–S6 是模拟实现，必须在**页面标注、接口响应 `"mock": true`、答辩口径**三处一致暴露，不得冒充真实能力（红线细则见 §4.1 与《02-测试场景.md》§5）。
4. **范围只做一次决定。** 本版确认的范围之外不再临时收回或砍掉；如确需变更，走 §6 的 PR 流程并在本文档登记。

### 1.4 范围结论

- **做**：M0、M1、M2、M3、M4、M5、M6、M7、M8、M9，模拟模块 S1–S6，以及 D01–D07 文档与交付。
- **新增范围（2026-09-23 用户要求）**：M7 医生社区基础论坛。S7 患者端仍不在本轮范围。
- **不建编号**：S7 保留编号位，M7 按下述增量范围实施。

**目标**：新机器一条命令拉起全栈；契约（`openapi.yaml`）成为前后端唯一事实源。

**交付项**

| 编号 | 交付项 |

### 3.2 M1 · 认证与数据范围 ｜ 依赖：M0 ｜ 量级：30h ｜ 状态：部分完成

**目标**：三种 2FA 渠道（邮箱 / 短信 / 人脸）任选其一完成登录；三个角色的功能权限与科室数据范围在所有模块上真实生效。

**交付项**

| 编号 | 交付项 |
|------|--------|
| M1-01 | 用户 / 角色 / 部门模型 + bcrypt + JWT 签发校验（`/api/auth/login`、`/verify-code`、`/logout`、`GET /api/me`） |
| M1-02 | 验证码服务（渠道无关）：签发 / 校验 / TTL / 一次性 / 限流 |
| M1-03 | 登录页 + 验证码页 + Token 存储 + 路由守卫 |
| M1-04 | RBAC 权限矩阵 + 接口鉴权（**声明式，禁止散落 `if role == …`**） |
| M1-05 | 科室数据范围过滤（service 层统一入口，admin 豁免） |
| M1-06 | 临时授权 `temp_grant` + APScheduler 到期回收 |
| M1-07 | 用户管理 CRUD + 角色/科室字典 + 前端用户管理页（`/api/users`、`/api/roles`） |
| M1-08 | 登录失败限速（密码与人脸 / 短信失败**共用同一计数器**） |

**完成标准**

- 权限矩阵**声明式配置**；越权返回 403 且 `message` 指明缺哪条权限。
- 权限失败**两套口径不可混用**：角色功能不足 → **403**；跨科室数据 → **404**。
- 匿名白名单显式声明，且**必须包含 `send-code`**。
- 三种 401（无 token / 过期 / 黑名单）`message` 可区分；`status=disabled` 持有效 token 亦被拒。
- `temp_grant` 表字段严格为 `(grantee_id, patient_id, reason, expire_at, is_valid)`，**不引入 `expires_at` / `status`**。
- 提供 3 角色 × 5 资源 = 15 组合的**期望结果表**，可脚本化回归。
- 提供匿名白名单、403/404 口径的自动化断言。
- 前端**路由级角色门禁**：无权限的菜单不出现，地址栏直输进入无权限页（不是白屏、不是空数据）。

**现状（2026-09-21 代码核对）**

- 已完成：`/api/auth/login`、`/api/auth/send-code`、`/api/auth/verify-code`、`/api/auth/logout`、`/api/me`、`/api/auth/signup(+verify)`、`/api/auth/face/login`、`/api/temp-grants`（增 / 查 / 删）、`/api/departments`；数据范围过滤已实现为统一入口 `patient_scope()`（`backend/app/patients.py`），并被患者、过敏、授权等接口复用；限速已实现（密码 5 次 / 300s → 429，见 `auth.py`；验证码发送 60s 冷却 + 每日上限，见 `otp.py`）。
- **M1-07 已完成**（2026-09-21）：`backend/app/users.py` 五条路由 + `GET /api/roles`；前端 `UserManagementView.vue` 与侧栏入口；`/api/users` 的**列表**读权限放宽为任意登录用户（写与详情仍仅 `admin`），因此 M5 的契约外路由 `/api/meetings/doctors` 已被删除，会诊邀请选择框改读 `/api/users?status=active`。验收见 `backend/tests/test_users.py`。
- 前端角色门禁已完成：`frontend/src/access.js` 的 `MODULE_ROLES` 是唯一事实来源，`router/index.js` 的守卫与 `App.vue` 的侧栏各自读它一遍，越权菜单不出现、地址栏直输进入 `/403`。
- **待确认**：M1-08 要求"人脸 / 短信失败共用同一计数器"。密码与验证码限速已实现，**人脸失败是否计入同一计数器未逐条验证**（`face_login.py` 走 `match_face()`，恒真路径下不会产生失败计数）。

## 4. 模拟实现模块（S1–S6）

### 4.1 模拟实现的统一约定与红线

| 约定 | 要求 |
|------|------|
| **provider 抽象** | 每个模拟模块必须有一个可替换的接口（`SmsProvider` / `FaceProvider` / `RecorderProvider` / `DeviceGateway` / `NotifyProvider`）。模拟实现是**其中一个实现**，不是把假逻辑写死在业务代码里 |
| **显式标注** | 所有模拟接口的响应体带 `"mock": true`；所有模拟界面有可见的"模拟"角标或横幅 |
| **红线** | **不得把模拟说成真实**。答辩 PPT、演示脚本、页面文案三处口径必须一致 |
| **可替换性** | 接入真实服务的改动应局限于 provider 实现 + 配置项，不改业务代码 |
| **文档同步** | 动到 `openapi.yaml` 的（如 `vital_sign.source` 增加 `device`），必须同步改 `docs/api/API-索引.md` |
| **不做后门** | 模拟器必须走**与真实设备 / 真实渠道相同**的接口，不得为演示单独开旁路 |

**红线细则（三条，缺一即判未通过）**：

1. **页面标注**：S2 人脸、S3 回放、S4 设备、S5 监控四处，界面上必须有可见的"模拟"角标 / 横幅。
2. **接口标注**：模拟 provider 的响应体带 `"mock": true`；`/metrics` 与模拟接口在 `openapi.yaml` 的描述字段写明 simulated。
3. **口径一致**：统一表述为"**模拟实现 + 可替换 provider**"，**不得出现**"已实现短信发送""已实现人脸识别""已实现通话录像"这类声明。

**模拟对象**：活体检测 + 人脸比对服务。**边界**：不做真实生物特征比对；**不存储任何原始人脸图片**（只存 SHA-256 指纹）；演示只用合成图片。

## 6. 认领与 PR 规范

**认领**

- 每个模块由 **1–2 人整体认领**，对该模块的**建表 + 接口 + 前端 + 测试场景全绿**负责。判定单位是"端到端闭环"，不是"后端接口写完"。
- 认领发生在**模块开始前**，不预先排到个人；每周末按 §5.2 的"出口判据"复核。未认领的模块在 §2 表中记为 `待认领`。
- 负责人只写**真实姓名**；本仓库**禁止**再使用单字母代号指代成员（旧排期文档的代号模型已作废）。

**分支与 PR**

- 一个模块一个分支、一个 PR，分支名形如 `feat/M4-emr-orders`（模块号必须在分支名里）。
- PR 描述必须引用**本模块的任务编号**（如 `M4-04`）与**测试场景编号**（如 `M4-T6`），并贴出场景实跑结果（截图 / 录屏 / pytest 输出）。
- PR 描述中**不得**出现旧编号 `T01–T37` / `M01–M07`（需要追溯时写"见《01-任务安排》§7"）。
- 契约需要变更时，**同一个 PR 内**同时改 `docs/api/openapi.yaml`、`docs/api/API-索引.md` 与实现。
- 跨模块共享能力（上传组件、provider 抽象、审计埋点辅助函数）由**首个需要它的模块**实现，其余模块复用，**禁止重复实现**。
- 破坏性横切改动（M9-01 ~ M9-04）必须在**同一个 PR 内**完成，不允许留中间态跨天。
- 状态列与本文档 §2 的一致性由 PR 提交者维护：**合并 PR 时同步更新本文档的状态列**，无代码不得写 `已完成`。

## 8. 技术选型与部署方式

### 8.1 数据库与中间件

| 项 | 决策 | 说明 |
|----|------|------|
| 主数据库 | **SQLite** | **不再是 MySQL 8.4**。单文件库（默认 `backend/doctor.db`），随 `backend/` 一起交付，零外部依赖 |
| 缓存 / 会话 | **Redis** | **认证的硬依赖**，不是可选组件 |
| Redis 的四个硬用途 | 1) 登录票据（ticket）2) 验证码（签发 / 校验 / TTL / 一次性）3) JWT 黑名单（登出即失效）4) 登录限流（发送冷却、失败计数、账号锁定） | **Redis 不可用时登录链路整体不可用**，但其余接口按 M0-03 口径仍返回 200 且 `redis:"down"` |
| 迁移 | Alembic | 空库 `alembic upgrade head` 一次成功；`downgrade base` 可回滚 |

> **已核对（2026-09-14）**：`compose.yaml` 与 `.github/workflows/ci.yml` 已同步为 SQLite + Redis —— compose 中无数据库容器、使用 `sqlite_data` 卷并设置 `DATABASE_URL: sqlite:////data/doctor.db`；CI 的数据库校验步骤已改名为 "Verify real SQLite and Redis security behavior"，备份校验步骤改为 "Verify scripts/backup.sh snapshots the SQLite database"。**旧的 MySQL 8.4 口径在仓库中已无残留。**

### 8.2 部署形态：`backend/` 自包含

- **全部后端运行产物部署在 `backend/` 文件夹内，自包含**：应用代码（`backend/app/`）、迁移（`backend/migrations/`）、依赖声明（`backend/pyproject.toml` + `uv.lock`）、环境文件（`backend/.env` / `.env.example`）、数据库文件（`backend/doctor.db`）、容器定义（`backend/Dockerfile`）都在同一目录下。
- 前端只依赖 `frontend/`，通过构建产物 / 代理访问后端；后端不依赖仓库根的额外脚本才能启动。

### 8.3 一键部署脚本（两套 + 转发壳）

| 平台 | 脚本 | 说明 |
|------|------|------|
| Windows | **`backend/start.ps1`** | 一键启动（安装依赖 → 迁移 → 起后端 → 起前端） |
| Linux / macOS | **`backend/start.sh`** | 同上 |
| 根目录（Windows） | `scripts/dev.cmd` | **退化为转发壳**，仅转调 `backend/start.ps1`，不再承载逻辑 |
| 根目录（Linux / macOS） | `scripts/dev.sh` | **退化为转发壳**，仅转调 `backend/start.sh` |

**现状（2026-09-14 已落地）**：`backend/start.sh` 与 `backend/start.ps1` 均已存在并自包含（准备 Redis、SQLite、Python 环境与前端，执行迁移与种子，再拉起 API 与前端）；根目录 `scripts/dev.sh` / `scripts/dev.ps1` / `scripts/dev.cmd` 已退化为**转发壳**，只额外保留 `docker` 模式。

**端口占用策略（2026-09-21）**：启动脚本只停止**可确证属于本项目**的遗留开发服务（判定逻辑在共用的 `backend/app/dev_runtime.py`，两侧脚本调用方式一致）。占用者无法确证归属时一律不停，打印其 PID、进程名和命令行后退出——这是有意保留的安全阀，用于防止在不自知的情况下连上陈旧的 API 实例。

### 8.4 演示数据

- 演示数据由 **`backend/app/seed_demo.py`** 承载，落库演示基线（账号表 / 患者表 / 过敏基线，见《02-测试场景.md》§4）。
- **为什么在 `backend/app/` 而不在 `scripts/`**：交付要求"全部后端运行产物部署在 `backend/` 内、自包含"，且容器镜像只 `COPY app`。放到 `scripts/` 会让 Docker 模式下启动脚本找不到模块。**本项已定，不再作为待确认事项。**
- **三层分工**（2026-09-21 增加第三层）：
  1. `backend/app/seed.py` 只写主数据（角色字典 `admin / senior / junior` + 三个科室）；
  2. `backend/app/seed_demo.py` 写演示账号、患者与过敏（§4 钉住的那些字段）；
  3. `backend/app/seed_flow.py` 写**全流程临床状态**：三种状态各一条问诊（含 55 条消息、1 张图片、1 通电话）、三种审阅状态各一条病历与 3 条医嘱、1 场已完成会诊（资料 + 报告 + 已过期授权）、1 份健康方案 + 3 条提醒规则 + 3 条提醒（1 条未读）+ 30 条体征 + 1 份评估，以及 `uploads/` 下 2 个占位附件。

  **每层依赖上一层**，缺失时直接 `SystemExit` / 非零退出并提示先跑上一层。
- **执行时机**：`backend/start.sh` / `backend/start.ps1` 与 Docker 的 CMD 在每次启动时依次执行 `app.seed` → `app.seed_demo`；**第三层只在 `scripts/build_db.py` 建库时执行**（可用 `--no-flow` 跳过），这样"重建库"给的是可演示的全量数据，而"启动"仍然只补不覆盖。开发模式下需要全流程数据时手动跑一次 `uv run python -m app.seed_flow`。
- **为什么单独一层**：前两层是"基线与账号"，第三层是"业务状态"。合并进 `seed_demo.py` 会让 §4 的漂移校验接口同时承担两份职责，也会让"只想要空工作台"的建库路径失去开关。
- **幂等**：只补缺失记录、**不覆盖**演示中被改过的数据。重复执行第二次输出 `0 account(s) and 0 patient(s) added, 4 and 3 already present.`；`seed_flow` 第二次输出 `0 row(s)` 并打印 `The full-flow baseline is complete.`。
- **「补不上」要如实报告**：演示中人自己建的行占住了基线想要的槽位时（例如已经为 P20260002 建过 Admission note），`seed_flow` **不写进那一行**，但 `--check` 会点名说清楚——不仅比行数，还按状态名检查 waiting / active / ended 与 draft / pending / archived。只比行数会漏掉这种情形：行数够，而审阅队列其实是空的。基线行数是**下限**不是等式，只有 `scripts/build_db.py` 对新库做逐表相等校验。
- **与 §3 场景的三条约束**（改动 `seed_flow.py` 时必须一并保持）：① 已结束问诊、已归档病历、已完成会诊都落在**上一个自然月**，否则 M3-T9「本月」筛选会多命中一条；② 预置的 `dr_chen` 临时授权**写死为已过期**，否则流程 2 第 2 步的「授权前 404」会因为已经可达而失去演示意义；③ 生命体征的 `is_abnormal` 由运行时函数 `app.health._is_abnormal` 现场算出，不抄结果，避免图表与接口对同一读数给出两种结论。
- **重置方式**：**没有 `--reset` 参数**（旧文档写的 `--reset` 不存在）。要回到干净基线，删除数据库文件 `backend/doctor.db` 后重跑启动脚本即可。
- **统一口令**：四名演示账号共用一个口令，取 `DEMO_PASSWORD` 环境变量，缺省 `Demo@2026`。仅因为是本地演示库才可接受，**不得用于任何对外环境**。
